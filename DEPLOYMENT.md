## PART 1: Setup MongoDB Atlas (Database)

### Step 1: Create MongoDB Atlas Cluster

1. **Go to** [https://www.mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register)
2. **Sign up** for free account
3. **Create a Project** → "Unique Brew Cafe"
4. **Build a Database** → Choose **M0 FREE** tier:
   - Provider: AWS (or GCP/Azure)
   - Region: **Singapore** (closest to SEA) or **Oregon** (fastest free option)
   - Cluster Name: `unique-brew-cluster`
5. **Create Cluster** (takes 3-5 minutes)

### Step 2: Configure Database Access

1. **Database Access** (left menu):
   - Click **"Add New Database User"**
   - Authentication Method: **Password**
   - Username: `admin` (or whatever you prefer)
   - Password: **Auto-generate** and **SAVE IT SECURELY**
   - Database User Privileges: **Read and write to any database**
   - Click **"Add User"**

### Step 3: Configure Network Access

1. **Network Access** (left menu):
   - Click **"Add IP Address"**
   - Click **"Allow Access from Anywhere"** (0.0.0.0/0)
   - Confirm

   ⚠️ **Note**: This is safe for free tier development. For production, restrict to your server IP.

### Step 4: Get Connection String

1. **Database** → **Connect** → **Connect your application**
2. **Driver**: Node.js, **Version**: 5.5 or later
3. **Copy Connection String**:
   ```
   mongodb+srv://admin:<password>@unique-brew-cluster.xxxxx.mongodb.net/?retryWrites=true&w=majority
   ```
4. **Replace `<password>`** with your actual password
5. **Add database name**: Change to:
   ```
   mongodb+srv://admin:YOUR_PASSWORD@unique-brew-cluster.xxxxx.mongodb.net/unique-brew-cafe?retryWrites=true&w=majority
   ```

✅ **Save this connection string** - you'll need it for Render!

## PART 2: Deploy Backend to Render

### Step 1: Prepare Your Repository

1. **Commit all changes**:

   ```bash
   git add .
   git commit -m "feat: Add Render deployment configuration"
   git push origin develop
   ```

2. **Merge to main** (Render auto-deploys from main by default):
   ```bash
   git checkout main
   git merge develop
   git push origin main
   ```

### Step 2: Connect GitHub to Render

1. **Go to** [https://dashboard.render.com/register](https://dashboard.render.com/register)
2. **Sign up** with GitHub (recommended)
3. **Authorize Render** to access your repositories

### Step 3: Deploy from render.yaml

1. **Dashboard** → **New** → **Blueprint**
2. **Connect a repository** → Select `unique-brew-cafe`
3. **Render will detect `render.yaml`** automatically
4. Click **"Apply"**

### Step 4: Configure Environment Variables

Render will create the service. Now add environment variables:

1. **Go to your service** → **Environment** tab
2. **Add the following environment variables**:

```env
# Required - Add these manually
DATABASE_URL=mongodb+srv://admin:YOUR_PASSWORD@unique-brew-cluster.xxxxx.mongodb.net/unique-brew-cafe?retryWrites=true&w=majority

CLOUDINARY_CLOUD_NAME=Unique_Brew
CLOUDINARY_API_KEY=161177217641536
CLOUDINARY_API_SECRET=e_WremLrh_-i7kNJuEgpXyDhIo8

# Optional - Email (leave empty if not using)
BREVO_API_KEY=

# These are auto-generated by render.yaml
JWT_SECRET=(already generated)
JWT_REFRESH_SECRET=(already generated)
```

3. **Update these after deployment**:
   - `FRONTEND_URL=https://your-frontend-app.vercel.app`
   - `ALLOWED_ORIGINS=https://your-frontend-app.vercel.app`

4. **Save Changes**

### Step 5: Wait for Deployment

- Render will automatically build and deploy
- Watch the **Logs** tab for progress
- Build time: ~3-5 minutes
- Look for: `✅ Build successful` and `Server running on port 10000`

### Step 6: Test Your Deployment

1. **Copy your Render URL**: `https://unique-brew-cafe-backend.onrender.com`
2. **Test endpoints**:
   ```bash
   curl https://unique-brew-cafe-backend.onrender.com/api/health
   ```
   Should return:
   ```json
   {
     "status": "ok",
     "timestamp": "2026-01-17T09:41:23.456Z",
     "uptime": 123.45,
     "environment": "production"
   }
   ```

## PART 3: Seed Database (Optional)

Run seeders to populate your database:

### Option 1: Via Render Shell

1. **Go to service** → **Shell** tab
2. **Run commands**:
   ```bash
   pnpm seed:admin
   pnpm seed:store
   pnpm seed:categories
   pnpm seed:products
   ```

### Option 2: Via Local Machine

1. **Update local .env** with production DATABASE_URL
2. **Run seeders**:
   ```bash
   cd apps/backend
   pnpm seed:all
   ```

## PART 4: Keep Free Tier Alive (Prevent Cold Starts)

Render free tier sleeps after 15 minutes of inactivity. Use a **cron job** to ping it:

### Option 1: UptimeRobot (Recommended)

1. **Go to** [https://uptimerobot.com](https://uptimerobot.com)
2. **Sign up** for free (50 monitors)
3. **Add New Monitor**:
   - Monitor Type: **HTTP(s)**
   - Friendly Name: `Unique Brew API`
   - URL: `https://unique-brew-cafe-backend.onrender.com/api/health`
   - Monitoring Interval: **5 minutes**
4. **Create Monitor**

### Option 2: Cron-job.org

1. **Go to** [https://cron-job.org](https://cron-job.org)
2. **Create free account**
3. **Create Cronjob**:
   - Title: `Unique Brew Health Check`
   - URL: `https://unique-brew-cafe-backend.onrender.com/api/health`
   - Schedule: **Every 10 minutes**

## 🔧 Troubleshooting

### Build Fails

**Error**: `pnpm: command not found`

- **Fix**: Render auto-detects pnpm. Ensure `pnpm-lock.yaml` exists in repo.

**Error**: `Cannot find module 'typescript'`

- **Fix**: Ensure `typescript` is in `dependencies` or `devDependencies` in `package.json`

### Runtime Errors

**Error**: "Cannot connect to MongoDB"

- **Check**: DATABASE_URL is correct (no `<password>` placeholder)
- **Check**: MongoDB Network Access allows 0.0.0.0/0
- **Check**: Database user credentials are correct

**Error**: "Port already in use"

- **Fix**: Render sets `PORT` automatically. Your app should use `process.env.PORT || 3001`

### Performance Issues

**Issue**: Slow first request (30s)

- **Cause**: Cold start (free tier sleeps)
- **Solution**: Use UptimeRobot to ping every 5-10 minutes

**Issue**: High memory usage

- **Check**: Render logs for memory warnings
- **Solution**: Optimize queries, limit connection pool (already done in config)
